-- MySQL Database: eduverse_db
CREATE TABLE users (
    user_id INT AUTO_INCREMENT PRIMARY KEY,
    full_name VARCHAR(120) NOT NULL,
    email VARCHAR(180) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    role ENUM('student', 'educator', 'evaluator') DEFAULT 'student',
    streak_days INT DEFAULT 1,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE user_learning_progress (
    progress_id INT AUTO_INCREMENT PRIMARY KEY,
    user_id INT NOT NULL,
    mindshift_completed BOOLEAN DEFAULT FALSE,
    whatif_score INT DEFAULT 0,
    errordna_score INT DEFAULT 0,
    escape_unlocked_level INT DEFAULT 1,
    overall_percentage INT DEFAULT 0,
    FOREIGN KEY (user_id) REFERENCES users(user_id) ON DELETE CASCADE
);
/ Module 01: MindShift

MindShift: Adaptive Learning

Topic: Database Normalization (1NF, 2NF, 3NF & BCNF). Switch explanation formats to fit your learning preference.

Ready

Simple View: Organizing a Cluttered Closet

The Everyday Analogy: Storing customer info, product details, and orders in one giant table is like stuffing socks, winter coats, and half-eaten food into one drawer. Normalization simply assigns clean, specialized drawers (tables) so every fact is stored in exactly one place.

Three Major Anomalies Prevented:

  • Insertion Anomaly: You cannot add a course until at least one student registers.
  • Deletion Anomaly: Removing the last student enrolled in Astronomy accidentally wipes the course definition from the database.
  • Update Anomaly: Changing an instructor's email requires updating 500 rows; missing one causes data contradictions.

1st Normal Form (1NF)

"One item per cell"

No comma-separated lists. Every cell contains atomic, indivisible values.

2nd Normal Form (2NF)

"Whole key dependency"

In 1NF with no partial dependencies on composite candidate keys.

3rd Normal Form (3NF)

"No middle-man dependencies"

In 2NF with no transitive dependencies between non-key attributes.

Detailed View: Functional Dependencies & Formal Decomposition

Normalization decomposes relational schema \( R \) to eliminate redundancy while preserving functional dependencies and achieving lossless join decomposition.

Functional Dependency Constraint:
X -> Y: IF t1[X] = t2[X] THEN t1[Y] = t2[Y]

3NF Definition:
For every non-trivial FD X -> Y:
Either X is a superkey OR Y is a prime attribute.

BCNF Definition:
For every non-trivial FD X -> Y: X must strictly be a superkey.
